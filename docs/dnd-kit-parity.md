# dnd-kit parity report (Epic #6)

Every capability dnd-kit documents, and what DnD does with it: **built** (DnD has it, maybe under
another name), **different** (DnD covers the need another way, on purpose) or **out of scope** (DnD
does not have it, and why). It lets the maintainer see the whole library against its reference
before publishing is planned.

dnd-kit is `../references/dnd-kit` (`clauderic/dnd-kit` at `ccaf3d5`, MIT, "Copyright (c) 2021,
Claudéric Demers"). It is a **study reference, never copied**: no DnD file is derived from it, so
`DERIVED` and `NOTICES` in `packages/core/tests/guard.test.ts` are still empty. The sources read are
its docs (`apps/docs/docs/**`, the current API and the `legacy/` one) and its packages (`abstract`,
`dom`, `collision`, `helpers`, `geometry`, `state`, `react`, `vue`, `solid`, `svelte`). Paths below
are relative to that folder. DnD paths are relative to this repository.

The architecture differs at the root, and most "different" rows follow from it: dnd-kit is a
manager with plugins, sensors and modifiers registered on it, behind a provider; DnD is a drag
space per document with no provider (D4), wrappers that clone their child (D6), the CSS
`translate` written by the core (D7, D8), and one entry per capability (D3).

Most "different" rows are the architecture (no provider, no plugin registry, no default text, the
core writing `translate`), not missing work. The "out of scope" rows are of three kinds: deliberate
(no modifiers yet, no drop animation, no HTML5 drag and drop, no shipped CSS), adapters that wait
for validation (Vue, Solid, Svelte), and dev tooling (Debug, the Storybook add-on).

## What the maintainer may want next

- **Modifiers** as pure functions per draggable (axis lock, bounds, snap): the most visible gap
  for users coming from dnd-kit, and cheap when each is its own export.
- **More collision strategies** (`closestCorners`, `pointerDistance`) as separate exports, if an
  example needs them.
- **Configurable keyboard bindings and a Shift multiplier** for the step mode, only if asked for.
- **The Vue, Solid and Svelte adapters**, once the React one is validated.
