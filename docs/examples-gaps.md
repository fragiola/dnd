# Gaps found while writing the examples

What the public surface could not express while the examples of Epic #1 and Epic #6 were written, what each
example does meanwhile, and where it is (or will be) answered. An example's workaround is commented
in its code, where readers copy it.

| #   | gap                                                                                                                                                                                                                                                                                  | the examples meanwhile                                                                                                                                                                                                                                                              | answered                                                                                                                                                                                                                                                 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | `DragOverlay`'s `className` and `style` functions were called while no drag ran, with `state.operation` undefined, though its type says it is always there.                                                                                                                          | `drag-overlay` gives the overlay a plain class (still a fine choice).                                                                                                                                                                                                               | Fixed in Epic #1's review: the overlay renders its content only while a drag runs, so its state functions always get an operation (`packages/react/tests/overlay.test.tsx`).                                                                             |
| E2  | The first `drag-over` of a drag reported the droppable it starts over, right after `drag-start`; an announcer that says every `drag-over` replaced the "Picked up" sentence before a screen reader read it.                                                                          | None any more (the `keyboard` narrator's skip is gone).                                                                                                                                                                                                                             | Fixed in Epic #1's review: the start target is resolved at the start, `drag-start` carries it, and `drag-over` reports only a later change (`packages/core/tests/operation.test.ts`).                                                                    |
| E3  | An arrow key pressed before a keyboard drag's first animation frame counted from no target: in `"targets"` mode it went to the first droppable in reading order, not the next one.                                                                                                   | None any more (the `keyboard` and `rtl` specs no longer wait for `data-dnd-over`).                                                                                                                                                                                                  | Fixed in Epic #1's review, with E2: the target is resolved when the drag starts, so the first arrow moves on from the source's droppable (`packages/core/tests/keyboard.test.ts`).                                                                       |
| E4  | Firefox's scroll anchoring can take the dragged element (moved by `translate`) as the scroll container's anchor: when the core clears `translate` after a cancel at the end of the range, Firefox scrolls the container back by as much (measured: 1032 px to 0). Chromium does not. | `auto-scroll` sets `overflow-anchor: none` on its list.                                                                                                                                                                                                                             | By design (S4, Epic #6): the packages ship no CSS, so the app sets `overflow-anchor: none` on a container whose children shift; every sortable and swappable example does, with a comment. Documented in the animating-shifts guide and the limitations. |
| E5  | A Fragiola palette class (`palette-danger`) is a plain CSS class: a Tailwind variant cannot apply it (`data-dnd-refused:palette-danger` compiles nothing).                                                                                                                           | `accepts-types` and `dockable-new-tab` render a small badge that carries the palette and is shown with `group-data-dnd-refused:`.                                                                                                                                                   | By design (Fragiola UI's palettes).                                                                                                                                                                                                                      |
| E6  | A Dockable panel clips its content, so a card moved by its own `translate` vanishes at the panel's edge.                                                                                                                                                                             | `dockable-panels` uses `translate={false}` and a `DragOverlay`.                                                                                                                                                                                                                     | By design (D9): the overlay exists for this. Documented in the Dockable guide.                                                                                                                                                                           |
| E7  | A card pressed while it still glides home (its at-rest transition on `translate`) moves away from the press point.                                                                                                                                                                   | The `styling-showcase` spec waits for the glide to end.                                                                                                                                                                                                                             | By design: the transition is the app's.                                                                                                                                                                                                                  |
| E8  | Grid Layout is not on npm, so no gallery example can import it.                                                                                                                                                                                                                      | The Grid Layout integration stays a playground scenario (`interop/grid-layout-item`).                                                                                                                                                                                               | Once Grid Layout is published (D12).                                                                                                                                                                                                                     |
| E9  | A keyboard sort into another group ends with the item in another parent: React mounts a new element there, so the core cannot give the focus back to the source it moved (it refocuses within a group).                                                                              | `sortable-keyboard` focuses the moved item from its ref once it mounts in its new list.                                                                                                                                                                                             | By design (D14): the new element is the app's. Documented on the keyboard page.                                                                                                                                                                          |
| E10 | Over a refusing group the preview stays where it was last, so a card dragged from the Backlog across Doing to Done (which refuses it) lands in Doing on release.                                                                                                                     | `kanban` and its spec show it: the refusing column is not marked `data-dnd-sorting`, so the app can grey it out. `support-dispatch` wraps each agent's column in a plain `Droppable` that accepts exactly what its group refuses: over it the sort rests, and the ticket goes home. | By design (S2: a refusing group is never entered). An app that wants "nowhere" on a refusal vetoes the drop in `space.use`, and the preview goes home.                                                                                                   |
| E11 | An empty group shows no placeholder while the dragged item (moved by its own `translate`) is over it: the landing is only where the item will go, not a box.                                                                                                                         | `kanban` outlines every group taking part (`data-dnd-sorting`); `sortable-dockable` uses `translate={false}`, so the item itself is the placeholder in the empty list.                                                                                                              | By design (S4): the placeholder is the app's.                                                                                                                                                                                                            |
| E12 | Grid Layout items each form a stacking context, so a card moved by its own `translate` from one `GridLayout.Item` into the next paints under it.                                                                                                                                     | The `interop/grid-layout-kanban` scenario uses `translate={false}` and a `DragOverlay`.                                                                                                                                                                                             | By design (D9): the overlay exists for this. Documented in the Grid Layout guide.                                                                                                                                                                        |
| E13 | A keyboard move to a slot, swap target or droppable outside its scroll container's visible area did not scroll there (auto-scroll follows the pointer only), so a long sortable list could not be sorted by keyboard past its fold.                                                  | None any more.                                                                                                                                                                                                                                                                      | Fixed in Epic #6's review: each targets-mode step scrolls its destination into view, `block: "nearest"`-like (`packages/core/tests/{keyboard,sortable,swappable}.test.ts`, `apps/playground/e2e/sortable.spec.ts`).                                      |
