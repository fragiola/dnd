`<Draggable id="a"><Card /></Draggable>` renders exactly `Card`'s element. The wrapper merges its
ref, handlers, `data-dnd-*` attributes, ARIA and structural style into that one element and
renders nothing else. The child can be a plain element or any Fragiola primitive
(`Dockable.TabSet`, `GridLayout.Item`, a Fragiola UI component).

## What the child must do

The child must be **one element that forwards `ref` and its other props** to a DOM element: a
DOM element does, and so does every Fragiola primitive. In development, no child, several
children, a fragment or text throw with a message saying so, and a child that never attaches the
ref is reported with `console.error` after mount. In production an invalid child renders as it
is, without the behaviour.

```tsx title="card.tsx"
// a component child forwards ref and props (React 19: ref is a plain prop)
function Card({ ref, ...props }: React.ComponentProps<"article">) {
    return <article ref={ref} {...props} className="card" />;
}

<Draggable id="a">
    <Card aria-label="Report" />
</Draggable>;
```

## How props merge

- **Handlers compose**: the wrapper's first, then the child's own (`onPointerDown`, `onKeyDown`, …).
- **`ref`** is merged: the wrapper's own, the `ref` given to the wrapper and the child's `ref` all
  receive the element.
- **`className`** is added to the child's, and **`style`** merged over the child's; both take a
  value or a function of the wrapper's state. The structural keys (`translate`, `touch-action`)
  always win.
- **Everything else** a wrapper does not know is forwarded to the element, so a wrapper is itself
  a valid child, and wrappers stack:

```tsx title="stacked.tsx"
<Droppable id="slot-1">
    <Draggable id="card-1">
        <li>Card</li>
    </Draggable>
</Droppable>
// <li data-dnd-part="draggable droppable" data-dnd-id="card-1" …>
```

Stacked parts are listed in one `data-dnd-part` (matched with `~=`), and the inner wrapper's id is
kept.

## The render prop

With no child to wrap, `render` gives the element, Base UI style: an element whose props are
merged with the wrapper's, or a function receiving the props to spread and the state.

```tsx title="render.tsx"
<Droppable
    id="basket"
    render={(props, state) => (
        <section {...props} aria-label="Basket">
            {state.over ? "Release to drop" : "Basket"}
        </section>
    )}
/>
```

## In Vue

The Vue components follow the same contract with Vue's tools. A component renders its **single
default-slot child** cloned, with its attributes, listeners, ARIA, structural style and template
ref merged in; its default slot is scoped with the part's state, the Vue form of a function of the
state; and `as` replaces `render` when there is no child to wrap:

```vue title="wrapped.vue"
<Droppable id="slot-1" v-slot="{ state }">
    <Draggable id="card-1">
        <li :class="{ over: state.over }">Card</li>
    </Draggable>
</Droppable>
<!-- <li data-dnd-part="draggable droppable" data-dnd-id="card-1" …> -->

<Droppable id="basket" as="section" aria-label="Basket" v-slot="{ state }">
    {{ state.over ? "Release to drop" : "Basket" }}
</Droppable>
```

A component child must render one root element that takes its attributes and template ref, as
every Fragiola primitive does. The development checks are the same: no child, several children, a
fragment (a `v-for`) or text throw, and a child that never receives the element or its attributes
is reported after mount. See [the Vue API](/docs/api/vue).

## In Angular

Angular adds behaviour to an element with an attribute directive, so there is nothing to clone:
the directives sit **on your own element** and add none. The main input is the part's id, the
options are inputs, the callbacks are outputs, and `exportAs` gives the part's state as a signal,
the Angular form of a function of the state. Directives stack on one element:

```html title="wrapped.html"
<li dndDraggable="card-1" dndDroppable="slot-1" #slot="dndDroppable" [class.over]="slot.state().over">
    Card
</li>
<!-- <li data-dnd-part="draggable droppable" data-dnd-id="card-1" …> -->

<section dndDroppable="basket" #basket="dndDroppable" aria-label="Basket">
    {{ basket.state().over ? "Release to drop" : "Basket" }}
</section>
```

The host's own attributes, classes, styles and listeners stay as they are; its template listeners
are on the element before the core's, so an app's `(pointerdown)` sees a press before dnd claims
it. Stacked directives share an input of the same name (`disabled`, `scope`, `data`), and a static
attribute with an input's name sets it (`type` on a `<button dndDraggable>`). A directive on an
`<ng-container>` throws in development, and a handle outside a source is reported. See
[the Angular API](/docs/api/angular).

## Two deliberate exceptions to the Fragiola rules

- **A wrapper that clones its child, not "`render`, never `asChild`".** Fragiola primitives render
  their own element and take `render` to change it. dnd exists to add behaviour to elements other
  code already renders (a Dockable tabset, a grid item, your card), so cloning the child is its
  primary form, and `render` is the alternative. This is a maintainer's decision for this
  library, recorded in its rules.
- **No single namespace.** Fragiola libraries export one namespace (`Dockable.*`). A namespace
  gathers every capability into one import, which defeats [paying only for what you
  import](/docs/concepts/capability-entries), so dnd's parts are named exports of their
  capability's entry: `Draggable` from `@fragiola/dnd-react/draggable`.

## Hooks, the lower layer

`useDraggable(options)` and `useDroppable(options)` return `{ state, props }`: spread `props`
(the registering `ref`, `data-dnd-*`, ARIA) onto one element yourself. See
[hooks](/docs/api/hooks).
